# Context And KB Publish Rules

## 目的

定义什么时候写入产品仓库的 `context/`，什么时候进入独立的 `kb-publish` 发布流程。

## `context/` 的职责

`context/` 存放：

- 已确认的产品知识
- 稳定规则
- 核心流程
- 值得长期保存的历史总结

不适合放入 `context/` 的内容：

- 高频变化的执行细节
- 明显未定稿的方案
- 仅用于某个短期版本的过程记录

## `kb-publish` 的职责

`kb-publish` 存放：

- 产品说明页
- FAQ
- 操作指引
- 流程说明
- 术语解释
- 项目案例摘要
- 发布工作流和发布产物

`kb-publish` 面向统一对外发布，不是产品 context 仓库的一层。

## 发布判断标准

一个内容进入 `kb-publish` 前，至少满足：

1. 别人会反复问。
2. 内容已经稳定。
3. 不依赖口头解释也能独立阅读。
4. 能回溯到产品仓库中的 `context/` 或 `raw/`。

## 发布顺序

建议顺序：

```text
raw -> context -> kb-publish
```

但如果某类原始资料已经足够稳定，也可以直接从产品仓库的 `raw/` 提炼到 `kb-publish`，前提是结论明确且可验证，并能回溯来源。
