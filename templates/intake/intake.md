## 文件说明

| 文件或目录 | 简要说明 | 处理提示 |
|---|---|---|
| source prd/ | 历史 PRD、版本需求或评审材料。 | 按版本从小到大阅读，用于归并当前事实；不要把版本演进直接写入功能正文。 |
| screenshots/ | 当前产品截图。 | 与 PRD 对照，优先用于确认当前页面命名、字段、列表、表单和交互。 |
| standard docs/ | 标准说明、培训材料、操作手册。 | 用于补齐用户视角和稳定使用口径。 |
| dev docs/ | 技术方案、架构说明、开发需求。 | 用于理解架构、配置、数据流和实现边界；若与历史 PRD 冲突，需结合当前截图和最新材料判断。 |
| release note.md | 发布记录。 | 用于版本时间线和能力上线口径；不替代当前功能正文。 |
| project/ | 项目过程或交付材料。 | 先归档 raw；只提炼已交付且可复用的事实。 |

## 外部工作项提示

- 文件名或目录名只要包含“云效”关键词，都需要调用 `yunxiao-devops` 处理。
- Excel/WPS 必须读取 hyperlink 关系；URL 可能隐藏在单元格链接里，不一定出现在可见文本中。
- 每个云效工作项至少需要归档主体详情、评论、动态/变更历史、附件元数据和可下载附件副本。
- 抓取数量需要校验：解析链接数、主体抓取数、评论检查数、动态检查数、附件检查数应一致。

## 写入偏好

- context 正文只写当前有效状态；历史演进写入版本记录。
- 用户指出遗漏或错误时，优先改写原章节、原表格和原状态机，不优先追加补充段落。
- 复杂列表必须写到筛选项、列表字段、操作按钮和权限范围。
- 复杂表单必须写到分组、字段来源、校验、默认值、引用和操作交互。
- 如果来源不足以确认当前事实，先写入 drafts 或标记待确认，不要编造成稳定 context。
